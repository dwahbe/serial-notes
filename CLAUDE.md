# CLAUDE.md

Serial Notes — a menu-bar-only macOS app that captures meeting audio, transcribes + summarizes locally, and exports Markdown. Product context: `README.md`. Design decisions (Liquid Glass, layout, typography, icons): **[DESIGN.md](DESIGN.md)** — don't re-litigate them here.

**Repo facts.** Public, MIT (github.com/dwahbe/serial-notes) — treat every commit, comment, issue, and PR as publishable; secrets live only in GitHub Secrets, never the repo. Bundle ID `com.serialnotes.app` (dev builds: `…app.dev`). Requires **Xcode 26+, macOS 26+, Swift tools 6.2**; target macOS 26 APIs freely (no back-compat). `AGENTS.md` is a symlink to this file — edit `CLAUDE.md` only.

## Build & Run

```bash
./scripts/run.sh          # build + wrap .app + launch (dev loop)
./scripts/build-app.sh    # build + wrap only (no launch)
swift test                # unit tests (SwiftPM — no .app needed)
```

- **Never `swift run`, never press Run in Xcode.** Both produce a raw binary (Xcode's lands in DerivedData under the *same* bundle ID as the wrapped app → duplicate menu-bar icons + frozen traced processes). LaunchServices-gated APIs (Login Items, URL schemes, notifications, bundle-ID-tied TCC) need a real `.app`; a raw binary crashes on the first such call (`bundleProxyForCurrentProcess is nil`). The scripts build → wrap into `.build/SerialNotes.app` → ad-hoc sign + entitle → `lsregister`. Open `Package.swift` in Xcode as an editor only; `run.sh` purges any DerivedData build it finds.
- **Dev flavor (side-by-side isolation).** When `SIGN_IDENTITY=="-"` (ad-hoc, the script default), `build-app.sh` stamps a `.dev` bundle ID + "Serial Notes (Dev)" name so a local build runs alongside a downloaded production install with separate TCC + UserDefaults; `Bundle.isDevBuild` then shows a "DEV" menu-bar tag. A real Developer ID skips all of this, so "DEV" can't reach a notarized build. **Not** isolated: voice profiles + storage dir (fixed absolute paths), shared across flavors. **Dev builds never self-update:** `UpdaterController` skips `SPUUpdater.start()` when `isDevBuild` (About shows "Disabled in dev builds") — they read the production appcast, so an accepted update would overwrite `.build/SerialNotes.app` with the production build in place.
- **`run.sh` kill scoping.** Every process kill is anchored to a `$ROOT`-absolute path (the wrapped `.app` binary, the raw `.build/$CONFIG` binary, repo DerivedData) — **never** the bare `SerialNotes` name or the `Contents/MacOS/SerialNotes` suffix, since a downloaded production app shares both. "Stop/kill the local app" always means this dev build, never a production install.

## Releases & distribution

```bash
./scripts/release.sh 0.2.0   # validate clean tree + smoke-build + tag + push → CI publishes
```

Pushing a `vX.Y.Z` tag triggers `.github/workflows/release.yml`, which builds → signs → notarizes → publishes → commits the appcast — **never publish locally** (build/notarize locally only to *test*; the tag already does it). **`release.sh` refuses to tag if HEAD == the last tag's commit** — `CFBundleVersion` is the commit count and Sparkle upgrades by it, so an unchanged build number means installed users never get offered the update. Everything else — versioning, DMG styling, signing/notarization order, Sparkle + the appcast counting proxy, install location/translocation, release-notes house style, CI secrets — lives in **[RELEASING.md](RELEASING.md)**.

## Architecture

SwiftUI + `@Observable` (Swift 6 concurrency); all UI types are `@MainActor`. `RecordingState` owns the capture + transcription seams (`AudioCapturing`, `TranscriptionSessionManaging` — production conformers `AudioCaptureService`/`TranscriptionService`, fakes in `RecordingStateLifecycleTests`) and drives the UI.

**Back-to-back recordings (capture-first overlap).** A new recording starts capturing the instant Record is pressed, even while the previous meeting is still finalizing; Stop takes effect at the press (capture halts, `stopDate` is the transcript's end) no matter what finalization is doing. Per-session state lives on `RecordingSession`; the `AudioFeedPipeline` buffers capture audio in per-side ordered streams and replays it when the transcription actor frees up (`attachTranscription`), reporting per-side `StreamingCoverage` that the final render honors (an incomplete stream never ships as a complete transcript — merge + interruption note). **The `TranscriptionService` actor only ever holds one session**: finalizations serialize (each session's attach awaits its predecessor's finalization), and every late-firing callback (capture errors, transcription errors, phase updates) is scoped by session id. Post-meeting side effects (naming banner — queued at the banner, exports, capture warnings) **defer while a successor records** and drop at quit. Quit is bounded on a session's *own* attach work (never on a predecessor's in-flight finalization, which drains fully); a quit that begins mid-wait flips in-flight finalizations to the bounded path via `awaitAttachOrQuitBegins`.

**Audio capture**
- **Two paths:** `AudioCaptureService` tries the CoreAudio process tap first (`SystemAudioTap` module), falls back to ScreenCaptureKit on any failure.
- **System audio = raw HAL IOProc, never AVAudioEngine.** The system path runs `AudioDeviceCreateIOProcIDWithBlock` + `AudioDeviceStart` directly on the tap-aggregate device. Do **not** switch it to `AVAudioEngine.inputNode.installTap` — AUHAL on a tap-aggregate device delivers **zero buffers silently** (engine reports running, IOProc is created, the callback never fires). The mic path stays on AVAudioEngine because the mic is a regular input device, not an aggregate.
- **Aggregate construction** (`SystemAudioTap.m`): a private aggregate with the **default output device as both `kAudioAggregateDeviceMainSubDeviceKey` and the sole `…SubDeviceListKey` entry**, plus the process tap as a sub-tap. The output is required as the **clock master** — a tap-only aggregate has no clock, so its IOProc never fires.

**Transcription** — [FluidAudio](https://github.com/FluidInference/FluidAudio) Parakeet streaming ASR + LS-EEND diarizer, on-device, cached in `~/Library/Application Support/FluidAudio/Models/`. Model download starts at launch from `SerialNotesApp.init` (so the banner can record before the popover opens); `RecordingState.start()` re-awaits `downloadModelsIfNeeded()` (idempotent) as a safety net. A high-accuracy second ASR pass at `endSession` re-transcribes the saved WAVs for the final transcript. `FinalTranscriptSegmenter` keeps its segments deliberately short (they drive midpoint speaker attribution on the shared system channel — don't widen its gap threshold to fix fragmented rendering); consecutive same-speaker segments are instead merged into one block at render time by `TranscriptTurnMerger`, after attribution + echo filtering, while the per-fragment entries stay unmerged for re-attribution and clip extraction.
- **Punctuation + capitalization:** Parakeet emits raw lowercase. `TranscriptRewriter` runs per finalized EOU as a detached task. Production `FoundationModelsRewriter` is an actor over Apple's on-device `LanguageModelSession` using **plain-text responses + greedy sampling** — not a `@Generable` schema; as of macOS 26.5 structured output echoes copy-edit tasks verbatim (the echo passes the word guard, silently disabling punctuation), so don't switch it back — with a **2s timeout** and a **word-equality guard** (lowercased-alphanumeric compare) that rejects any rewrite that changed a word. **FM sessions are stateful and overflow their context window if reused** — both the rewriter and summarizer create a fresh session per request. When Apple Intelligence is off the factory returns `HeuristicRewriter` (deterministic sentence-splitting + casing). `endSession` races the rewrite drain against a **5s hard timeout** then cancels stragglers so a wedged FM call can't hang "Stop"; cancelled tasks short-circuit before writing back.
- **Summary + action items:** `TranscriptSummarizer` is constructed at session start (if either toggle is on) and prewarms during recording (hides cold-start); the real call runs once in `endSession()` after the transcript is finalized on disk. Single-pass vs map-reduce is decided by **measured token counts against `contextSize`** on macOS 26.4+ (`tokenCount(for:)`), falling back to conservative word counts below 26.4 — so the threshold scales automatically when a newer OS grows the window. **The factory returns `nil` when Apple Intelligence is off — there is no heuristic fallback, because a fabricated summary is worse than none.** The splice reads `transcript.md` back, inserts `## Summary` + `## Action items` between the header and the first entry, writes atomically, and is **idempotent per section** (an already-present heading is never re-spliced, but pending manual notes still land above an existing generated block instead of being reported as a failure).
- **Summary cutoff (auto-stop):** a `.callEndedAuto` stop threads `MeetingCallEndContext.inactiveAt` through `endSession(summaryCutoff:)` into `TranscriptFormatter.summaryInput(from:cutoff:)`, which drops entries **after** the cutoff from the *summary input only* — they stay in the on-disk transcript (keeps post-call hallway audio out of the summary). Manual, quit, and `.captureFailed` stops pass `nil`.
- **Direct send to apps (`MeetingExporter`):** opt-in `ExportSettings` toggles (default off) push the finalized `transcript.md` *into* an app after each meeting — **Apple Notes** via in-process `NSAppleScript` (HTML body, a "Meeting Notes" folder; needs the apple-events entitlement + a one-time Automation prompt; local IPC, no network) and **Bear** via a `bear://x-callback-url` opened with `NSWorkspace`. Targets are snapshotted into `StopContext` in `requestStop`; `finishStop` routes the export through the **deferred post-meeting actions** queue (semantics in **Back-to-back recordings**) — fire-and-forget because the first Notes send blocks on the TCC prompt, deferred FIFO because a Bear export would activate Bear mid-meeting. Best-effort — every failure is `NSLog`-and-continue; the on-disk transcript is always the source of truth. The pure Markdown→HTML/strip helpers are `internal` + unit-tested (`MeetingExporterTests`). The setup guide's Apple Notes / Bear tiles (`NotesDestination.pushTarget`) flip the matching toggle instead of creating a folder.
- **Notion export (issue #8):** the third `ExportTarget` — the one direct-send target that delivers over the network instead of locally (opt-in, default off). It rides the same deferred post-meeting queue via an **injected `NotionSending` seam** (`RecordingState.notionSender`, production conformer `NotionConnection`) — the static `MeetingExporter` can't carry connection state. `StopContext` snapshots **destination identity (workspace + page ID), never tokens**; **availability = connected, not installed**. OAuth via the site proxy, the Keychain credential rules, and the API failure/self-heal rules: **[NOTION.md](NOTION.md)**.

**Manual notes**
- **Owned notepad, not an external editor.** A Serial Notes-owned Markdown notepad lets the user jot notes *during* a recording; at finalization non-empty notes splice into `transcript.md` as `## Notes` **above** `## Summary` / `## Action items` (`TranscriptFormatter.topSections`), so every export destination gets them. The notes section closes with an invisible HTML-comment sentinel (`TranscriptFormatter.manualNotesEndMarker`): entry-grammar consumers (`parseEntries`, `relabelSpeaker`) treat everything inside as user prose, so a pasted transcript-style quote can't become a phantom speaker or truncate the relabel region; `MeetingExporter` strips the sentinel from exports, and a missing sentinel (legacy or user-deleted) degrades to plain grammar scanning. It does **not** edit the AI transcript — it only adds a user-authored section, so it doesn't violate the "no in-app transcript editor" principle. Opt-in `ManualNotesSettings.openNotepadWhenRecordingStarts` (default off); manual "Open Notes" in the popover; and a **global toggle shortcut** (default ⌃⌘N, user-configurable in Settings → General → Notepad via the `sindresorhus/KeyboardShortcuts` package — Carbon `RegisterEventHotKey` underneath, so it fires over fullscreen meeting apps with no Accessibility/TCC prompt, but not during secure keyboard entry) whose registration is **recording-scoped**: claimed at the notes bind in `start()`, released at the stop press, so outside a session the combo passes through to other apps (a combo recorded while idle is immediately re-disabled by `shortcutDidChange`). The name + default live in `KeyboardShortcuts.Name.toggleNotepad` (ManualNotesWindowController.swift); UI hints must read the live combo from `ManualNotesWindowController.shortcutDisplay`, never hardcode it. The package ships localized strings and is **vendored at `Vendor/KeyboardShortcuts` with a patched bundle accessor** (see its `VENDORED.md`): stock SwiftPM `Bundle.module` only checks the `.app` root and the build machine's absolute `.build` path — never `Contents/Resources/`, the only location code signing allows — so an unpatched resource-bearing package works on dev machines (the `.build` fallback exists locally) and fatalErrors on user machines (this shipped the v0.2.3/v0.2.4 crash on opening Settings). `build-app.sh` copies every SwiftPM `*.bundle` into `Contents/Resources/` and refuses to wrap a bundle from a package not on its patched allowlist.
- **Floating panel, not a `Window` scene.** `ManualNotesWindowController` owns an `NSPanel` (`.nonactivatingPanel` + `.floating` + `canJoinAllSpaces`/`fullScreenAuxiliary` + `canBecomeKey`), like `MeetingBannerController`, so it overlays a full-screen Zoom/Meet Space — a `Window` scene would be stranded on another Space. Stays `.accessory`; don't reintroduce a scene-based notepad.
- **Draft lifecycle (`ManualNotesStore`):** the in-memory `text` is the source of truth handed to `endSession(manualNotesMarkdown:)`; the hidden `.manual-notes.md` sidecar in the session dir is **crash-safety only**. All sidecar I/O (debounced autosave, final snapshot, reap) runs on an **ordered off-main disk chain** (storage may be an iCloud/Obsidian vault — never block typing on disk), so a stale in-flight write can't resurrect a reaped sidecar or clobber a newer snapshot. `requestStop` captures the draft synchronously into a **`ManualNotesSnapshot` value token** that travels with that session's finalization (`snapshotAndEndSession` frees the active-draft slot immediately, so a back-to-back recording binds notes at capture start); `completeSnapshotWrite(_:succeeded:)` deletes the sidecar on a committed splice, and on failure **re-verifies the sidecar write before claiming it's saved**, stashes a pointer into a UserDefaults **list** that `restoreQuitRecoveryDraft()` consumes one-per-launch, and re-activates/re-presents the notepad **only when no newer draft owns it** — a live successor gets an attributed deferred message instead (never its predecessor's error in its own notepad). Unattached finalizations (attach failed, quit gave up waiting) run the same recovery. A kept draft (failed splice, quit recovery) **carries forward into the next `beginSession`** instead of being wiped; empty drafts touch no disk at all. Summary/action-items input **excludes** the notes — they splice *after* `summaryInput` is read from the body.
- **Editor gotchas (`ManualNotesMarkdownEditor`):** live-styled **TextKit-1** `NSTextView`, dense with load-bearing comments — **read them, plus the pinning `ManualNotesMarkdownEditorTests`, before changing anything**; the hard-won invariants (uniform line height, hidden 0.1pt markers, list nesting + tab collapse, `OrderedMarker`, restyle scoping) are all documented at their call sites. Two cross-file seams: the inline grammar lives once in `MarkdownInlineParser`, consumed by both the editor and `MeetingExporter`'s HTML export — extend it there, never as a separate loop or regex — and list-indent depth likewise comes from the shared `TranscriptFormatter.listIndentLevel`. The one invariant to restate here: **selection changes must never mutate the text storage synchronously** — on macOS 26 text renders via a private window-server-managed `ContentLayer`, and storage edits inside the selection-change transaction can blank the selected lines (the custom-drawn bullets survive because `draw(_:)` output lives in the view's own layer).

**Voice & identity**
- **Enrollment:** `VoiceProfileStore` persists profiles to `~/Library/Application Support/SerialNotes/voices/` as `<uuid>.json` + `.wav` pairs (plus a derived `<uuid>.embedding` cache — see `VoiceEmbedding`); decoded clips are cached and invalidated by `reload()` (runs after every save/rename/delete). On session start, `RecordingState` primes each diarizer with the enrollment clips so matched voices get named instead of `You` / `Person N`.
- **Preferred name** (`IdentitySettings.yourName`, optional, works without enrollment): `micDisplayName` (the name, or `You`) is the single mic-voice label that **three sites must agree on** — the streaming default label (`labelForSpeaker`), the `.you` diarizer enrollment label, and the final-render `CrossChannelEchoFilter.normalizeMicLabels` target. Keep them in lockstep.
- **Post-meeting speaker naming:** unnamed system-side speakers get a `speakers.json` sidecar in the session folder; their audio clips are quarantined in app-support `pending-speakers/`, **never the user's storage folder**, so the "only `transcript.md` is kept" promise holds. `MeetingSessionsStore` (Meetings tab) names a speaker via profile upsert → idempotent transcript relabel → sidecar update → clip reap, ordered so a retry never strands the user. Relabel is whole-word and scoped above the first speaker entry, so "Person 1" never clobbers "Person 10" and body quotes are untouched.

**Meeting detection**
- **Edge-triggered start.** `MeetingInputCaptureMonitor` watches each known meeting app's `kAudioProcessPropertyIsRunningInput` and emits the set of bundle IDs currently capturing; the pure `MeetingStartDetector` reducer prompts only when a known app **freshly starts** capturing and sustains it past a debounce. This is the idle-Zoom-false-positive fix: warm-holding the mic with no call produces no transition. Anything already capturing at monitor start is the baseline and never prompts (launch mid-call → no auto-prompt; manual record still works). One prompt is locked at a time; where the per-process API yields nothing, nothing prompts — **there is no focus-order fallback** (that was the original false-positive source; don't add one). **The monitor observes through recording + finalization — never re-add a session gate to `shouldMonitorInput`**: a blind window swallows the next call's edge and back-to-back meetings can then never prompt (the July 2026 bug). Only prompt *surfacing* is gated (the reducer's prompt gate, closed while `isStarting || isRecording`); a candidate maturing mid-recording defers and surfaces at the stop press, and the reducer's lock is consumed at recording start (into the call-end association), not released at stop. A deferral only ever surfaces against **live** capture state: the service skips `promptGateOpened` while the monitor is down or the app is quitting (`prepareForTermination`), and a monitor restart carries the deferral + episode suppressions into the fresh reducer (`init(resumingFrom:)`) to surface — or clear — on its first live snapshot.
- **Reliability invariants:** CoreAudio per-process notifications **drop for some apps (notably Zoom)**, so both monitors keep polling safety nets (~1.5s start / 3s call-end) — don't remove them. A failed `readProcessObjectList()` must **preserve the last-known set**, never report "nothing capturing", or an ongoing call looks ended and re-prompts on recovery. The banner's 15s auto-dismiss routes through `dismiss()` (not a bare `hide()`) so it releases the reducer lock instead of wedging a stale offer. Timer durations live on the reducers (`debounceSeconds` / `inactiveGraceSeconds` / `countdownSeconds`); the service reads them so they can't drift (defaults: 2s grace, 5s countdown).
- **Auto-end.** Only when the start prompt's lock was consumed into the session's association at gate close (`pendingAssociationBundleID` — read once and cleared at the recording's rising edge, so a successor can never inherit it) does `MeetingAudioActivityMonitor` attach for call-end — so **manual recordings never auto-stop** and can't be killed by an idle app releasing the mic. Activity feeds `CallEndStateMachine`; auto-stop fires `.callEndedAuto` carrying the summary cutoff. "Keep Recording" suppresses **per-recording** (the state machine) — distinct from the start detector's **per-episode** suppression; don't conflate them. Toggle: `MeetingSettings.autoStopAfterCallEnds` (on by default).
- **Prompt surface:** `MeetingBannerController` is a borderless `NSPanel` at `.statusBar` level with `canJoinAllSpaces + fullScreenAuxiliary` so it floats over fullscreen Zoom and follows spaces. The end-call prompt shows no countdown and only a "Keep Recording" escape hatch; it dismisses on activity resume / Keep Recording / stop / auto-stop, never on a timer.

**App shell**
- **Single-instance guard** (`SingleInstanceGuard`): LaunchServices dedupes launches by *path*, not bundle ID, so a stale copy (Raycast/Spotlight, `~/Downloads`) can start a second production instance. Two phases: `enforce()` in `applicationWillFinishLaunching` handles the fast paths — the running instance wins, the duplicate activates it and exits before the menu-bar icon appears; instances are liveness-checked with `kill(pid, 0)`, never `isTerminated` alone (KVO lags — a dead-but-listed entry right after a Sparkle relaunch must not be deferred to). UI-bearing flows are stashed and run by `resolvePendingConflict()` in `applicationDidFinishLaunching` **before `moveIfNeeded`** (pre-finishLaunching alerts can land behind the frontmost app): **orphan reclaim** (executable trashed/deleted under a running process; detected via `proc_pidpath`, not `bundleURL`, since an install may have refilled the original path) and the **DMG Quit-and-Install offer** (read-only *resolved* source = install intent; an unresolved AppTranslocation mount is explicitly *not* install intent). Waits **sleep, never pump the run loop** (pumping would execute the doomed instance's queued init work), and `SerialNotesApp.init` holds the model download back while a peer instance runs. **Never `forceTerminate()`** — quit must drain finalization; on timeout the guard explains and steps aside. **Dev builds skip the guard** (`run.sh` owns their lifecycle; a second worktree's dev build would otherwise turn `run.sh` into a silent no-op launch). Pure `decide(…)` reducer + `SingleInstanceGuardTests`. `moveIfNeeded` confirms before a **downgrade** (older DMG over newer install, `CFBundleVersion` compare) and installs **stage-then-swap** so a failed copy never costs the working install.
- **Activation policy.** This is an `.accessory`/LSUIElement app and **stays `.accessory` for its whole lifetime — nothing ever flips to `.regular`** (that parks a Dock icon + Cmd-Tab entry for the duration). Every window and modal — the setup guide, Settings, the storage `NSOpenPanel` — is surfaced the menu-bar way: `NSApp.activate()` + `orderFrontRegardless()`. `WindowBringToFront` does this in `viewDidMoveToWindow` and reports the window back through its `onWindow` hook; Settings uses that to stash itself in `SettingsNavigation.settingsWindow`, so the menu bar + post-meeting prompt can re-front it on a repeat open (the once-only `viewDidMoveToWindow` can't). It also re-fronts on `didBecomeActive` when built with `keepFrontOnReactivate:` (Settings + the guide both opt in) — a system permission prompt (mic/system audio) or a System Settings round-trip resigns the app, and an `.accessory` window won't auto-raise afterward. `WindowCloseChrome` now only runs its `onClose` teardown (the setup guide resuming detection) — there's no activation policy left to restore. `UpdaterController` (`@Observable`, builds `SPUUpdater` + a custom `QuietUserDriver` by hand — the `SPUStandardUpdaterController` wrapper gives no hook to replace the verbose "no update found" alert — and mirrors KVO `canCheckForUpdates`) calls `NSApp.activate()` before update alerts — without it a scheduled prompt appears *behind* other apps.
- **First-run guide** (`OnboardingFlowView`, a `Window` scene): mic + system-audio permissions → Apple Intelligence → storage → optional voice. `OnboardingSettings` persists `hasShown`/`completed` in UserDefaults (survives Sparkle's in-place `.app` replacement, so it never re-triggers on update). It calls `markShown()` in its **own `.onAppear`** (not at the decide-to-open point), so a failed `openWindow` retries next launch instead of suppressing onboarding forever, and it owns `suspendDetection()`/`resumeDetection()` for its whole lifetime.
- **System-audio permission** (`SystemAudioPermission.swift`): macOS has no *public* status API, so `systemAudioAuthorizationStatus()` reads the decision via the private `TCCAccessPreflight` symbol (the process-tap grant lands under `kTCCServiceAudioCapture` — confirmed on macOS 26; `kTCCServiceScreenCapture` is also checked as a belt-and-suspenders; `.undetermined` if the symbol won't resolve). The prompt is fired separately by `triggerSystemAudioPrompt()` — **building the tap alone doesn't prompt; TCC only engages once an IOProc actually runs**, so it briefly starts + tears down a capture (off-main, since the tap dance stalls). **Critical quirk: TCC caches a service's status per-process, so the app that fires the prompt can *not* observe the grant it just received — only a later launch reads the true value.** Mic has a live API (`AVCaptureDevice.requestAccess`) and confirms instantly; system audio cannot. So the setup guide shows the ✓ **optimistically** once the user answers the prompt (detected by the app reactivating, `didBecomeActive` + `awaitingSystemAudio`; since system audio has no `requestAccess`-style completion and an `.accessory` app won't reactivate itself after the prompt, the guide pulses `NSApp.activate()` until the system prompt closes — `reclaimActivationAfterSystemAudioPrompt` — to reclaim focus, so the ✓ lands without a manual click) — it may show ✓ even on a denial; the real value is read on the next launch, and the capture path degrades gracefully if absent.

## Conventions

- **CoreML inference must never dispatch to the GPU.** Every FluidAudio model load routes through `ModelComputePolicy` (CPU+ANE; hidden `inference.allowGPU` defaults key re-admits GPU for A/B after an OS fix). Never construct a FluidAudio manager/model with its default config — `MLModelConfiguration()` means `.all`, and on macOS 26.5.x that sustained GPU inference triggered **system-wide GPU MMU-fault storms** (`gpuEvent-*.ips` in `/Library/Logs/DiagnosticReports/`) that corrupted rendering in every GPU client (Arc, Claude Desktop, WindowServer) mid-meeting. Upstream nil-defaults still resolve to `.all` (e.g. `OfflineDiarizerModels.load`'s `configuration`), so every load site passes the policy configuration/units explicitly — `ComputePolicyGuardTests` sweeps the tree for call sites that drop them. `session.json` records `inferenceComputeUnits` per session.
- **Networking is minimal — everything runs locally.** Only four exceptions, and a fifth needs justification: FluidAudio model downloads (Hugging Face, first launch), Apple on-device Foundation Models (may pull its base model via system channels outside our control), Sparkle update checks (the `serialnotes.app/appcast.xml` proxy + GitHub archives; no profiling sent — the proxy counts the check anonymously, see [RELEASING.md](RELEASING.md), but the app sends nothing beyond Sparkle's stock request), and the **opt-in Notion export** (OAuth handshake via the `serialnotes.app` proxy, transcripts app → `api.notion.com` directly; off by default — see [NOTION.md](NOTION.md)).
- **Transcript post-processing splits by scope.** Per-utterance mutations (punctuation/capitalization — anything touching one EOU) go in `TranscriptionService`'s EOU handlers; the 3s `flushOldEntries` delay gives detached rewrites headroom to land before their slot flushes — don't add a separate per-entry post-write pass. Whole-transcript passes (summary, action items) go in `endSession()` after the file is finalized, mirroring `spliceTopSections`: read back, mutate, write atomically.
- **Any feature that opens the mic outside a recording session** (e.g. `VoiceEnrollmentRecorder`; the onboarding guide too) must bracket its engine lifetime with `MeetingDetectionService.suspendDetection()` / `resumeDetection()`, or it false-fires the "meeting detected" banner. (Enrollment wiring lives in `SettingsView.PeopleSettingsTab.onAppear`.)
- **Any programmatic stop must route through `RecordingState.stop(reason:)`** (or `stopAndWait(reason:)` to await finalization, e.g. app quit) with a `RecordingStopReason` — never bare `stop()`. The reason is written to `session.json`; keep summary-cutoff logic flowing through `RecordingStopReason.summaryCutoffDate`, not state-machine internals.
- **Adding a meeting app = one row** in `MeetingDetectionService.knownMeetingApps` (`displayName` + `coreAudioBundleSubstrings`). Both the start path and the call-end monitor read this table — don't add a parallel switch elsewhere. New meeting prompts extend `MeetingBannerController`; don't add `UNUserNotificationCenter` flows without working through Focus/DND filtering + notification-permission UX.
- **Audio output:** timestamped session dirs with `system.wav` + `mic.wav` (mono float32; system @48kHz, mic at its hardware rate), a streaming `transcript.md`, and a `session.json` sidecar (`stopReason`, summary cutoff, meeting diagnostics). **WAVs are always written during capture** — second-pass ASR, summary splice, and clip extraction all read them — then deleted at the end of `endSession` unless `StorageSettings.saveAudioFiles` is on. A hidden `.manual-notes.md` draft sidecar may sit alongside during recording; it's reaped after the `## Notes` splice and kept only if that splice failed (see **Manual notes**).
- `Info.plist` + `SerialNotes.entitlements` are **real files** wrapped/applied by `build-app.sh` (Info.plist copied into `.app/Contents/`; entitlements via `codesign --entitlements`, not a linker `__info_plist` hack). Entitlements: `com.apple.security.device.audio-input` + `com.apple.security.automation.apple-events` (the latter for the Apple Notes exporter, paired with `NSAppleEventsUsageDescription` in Info.plist). The apple-events entitlement is applied identically to ad-hoc dev and Developer ID builds, so the Notes Automation prompt **can** be tested from a `./scripts/run.sh` dev build (its grant is keyed to the `.dev` bundle ID, separate from production; reset with `tccutil reset AppleEvents com.serialnotes.app.dev`).
- **TCC permissions are bound to the `.app` path** — a different worktree = different path = re-prompts. Expected.
- **Keep testable code `internal`** (the test target uses `@testable import SerialNotes`). `private` types can't carry `@Generable` (or other macro-expanded conformances) — that's why the rewriter/summarizer schemas are top-level structs, not nested in their actors.
- Voice profiles live under `~/Library/Application Support/SerialNotes/voices/` — don't store other personal data there.

## Marketing site

A self-contained **Astro + Tailwind v4** project under `site/`, using **bun**. SwiftPM compiles only the explicit `path:` targets under `Sources/`/`Tests/`, so `site/` is never part of the macOS app build.

- **Dev:** `cd site && bun install && bun run dev` (localhost:4321) · **Build:** `bun run build` → `site/dist/`
- **Deploy:** Vercel, dashboard **Root Directory = `site/`** (invisible from repo files). `site/vercel.json` pins `framework: astro` + an `ignoreCommand` that skips the build when a commit doesn't touch `site/`.
- Site copy + links live in `site/src/consts.ts` (`SITE`); `astro.config.mjs` duplicates `SITE.url` — keep them in sync.
- **Server routes:** the site is static-first via `@astrojs/vercel`; only `/appcast.xml` (Sparkle counting proxy — see [RELEASING.md](RELEASING.md)), `/admin` (password-protected analytics dashboard: GitHub download counts + daily update-check chart), and the Notion OAuth pair `/oauth/notion/start` + `/api/notion/token` (see [NOTION.md](NOTION.md); the two `/oauth/notion/*callback` bounce pages stay static) opt into on-demand rendering with `prerender = false`. Analytics backing store is the "Serial Notes" Supabase project (`kwkgrtoaduryfdgqjnwf`): an aggregate-only `appcast_pings` table (day, version, count — RLS with zero policies) plus a `record_appcast_ping` RPC that is the anon key's *only* capability; reads require the secret key. **Privacy invariant: never store IPs, identifiers, or per-event rows — aggregate counters only; the Notion token routes store and log nothing.** Env vars (Vercel + local `.env`, see `site/.env.example`): `ADMIN_PASSWORD`, `SUPABASE_SECRET_KEY`, `NOTION_CLIENT_ID`, `NOTION_CLIENT_SECRET`, optional `GITHUB_TOKEN`; the Supabase URL + publishable key are public by design and live in `site/src/lib/analytics.ts`.
